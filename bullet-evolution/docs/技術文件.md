## 2. 兩套基因系統

遊戲有**兩套獨立的基因演化系統**，共用同一套設計哲學但參數完全不同。

### 2.1 敵人基因（6 系 × 10 基因 × 族群 10）

六個始祖系定義於 `LIN`：

| # | 系名 | 陣型 `f` | 移動 `mv` | 攻擊 `pat` | 彈形 `sh` | 行為 `mod` | 繁殖權重 `k` |
|---|------|---------|---------|-----------|-----------|-----------|------------|
| 0 | 針蜂 | V字 | 0 | 0 扇形 | 1 針彈 | 0 | 5 |
| 1 | 水母 | 散開 | 3 | 0 扇形 | 3 大球 | 5 爆裂 | 3 |
| 2 | 砲蟹 | 橫列 | 2 | 1 彈牆 | 0 圓彈 | 0 | 3 |
| 3 | 獨眼 | 兩側 | 0 | 3 光束 | 0 圓彈 | 0 | 2 |
| 4 | 孢子 | 弧線 | 3 | 0 扇形 | 2 菱形 | 4 追蹤 | 4 |
| 5 | 雨雲 | 散開 | 2 | 2 落雨 | 0 圓彈 | 0 | 2 |

十個基因 `a` 的順序固定為：
`[血量, 體型, 速度, 擺幅, 擺頻, 色相, 射速, 彈速, 數量, 瞄準]`

**系的身分（不可變）**：`pat`（攻擊類型）、`sh`（彈形）、`mv`（移動行為）、
`l.a`（十基因錨點）。`mate()` 產生子代時這三項直接繼承父代，**不參與突變**。

**基因表型**（`ex()`）：

| 基因 | 表達式 | 範圍 |
|------|--------|------|
| 血量 | `(3 + v[0]*14) * pw * CFG.hp` | — |
| 體型 | `.035 + v[1]*.04` | 0.035–0.075 |
| 速度 | `v[2]` | 0–1 |
| 擺幅 | `v[3]*.3` | 0–0.3 |
| 擺頻 | `.8 + v[4]*2` | 0.8–2.8 |
| 色相 | `v[5]*360` | 0–360 |
| 射速 | `(.25+v[6]*1.4)*CFG.rate*(1+(pw-1)*.6)` | — |
| 彈速 | `(.25+v[7]*.4)*sv*(1+(pw-1)*.3)` | — |
| 數量 | `1 + round(v[8]*5 + (pw-1)*3)` | — |
| 瞄準 | `v[9]` | 0–1 |

彈形放大係數 `sv = [1, 1.5, 1.1, .65][sh]`（圓彈/針彈/菱形/大球）。
彈體半徑 `r = .014 * [1, .7, 1, 1.8][sh]`。

**遺傳（`mate()`）**：
1. 逐基因 50% 機率取父、50% 取母
2. 10% 機率突變，突變量 `g3()*.25`，其中 `g3 = R()+R()+R()-1.5`（三方和，標準差 ≈ 0.5）
3. 色相基因（index 5）循環取模，不做 0–1 clamp
4. 拉回錨點：
   ```
   pull = .015 + .04*(1 - cos(π*d))     // d = |y - a[i]|
   y += (a[i] - y) * pull
   ```
5. 4% 機率發生**結構突變**：三分之二機率換 `pat`、換 `sh`、換 `mod`（各占 1/3）

**拉回函數是 bump 不是衰減**：`d=0` 時 pull=0.015、`d=1` 時 pull=0.095。
平衡點推算：突變變異數 ≈ 0.1 × 0.0156 = 0.00156，除以拉回強度，
穩態離散度約 **12%**。→ **敵人演化會長期在離始祖先 12% 附近擺動，不會跑遠。**
這是刻意設的天花板，圖鑑面板的「離始祖 %」數值會長期顯示 10 出頭。

**波末演化（`evolve()`）**：
```
適應度  fit = hits*3 + alive*.08
過熱    hot = hits > 4           // 單隻命中超過 4 次視為太兇，不留種
親代    par = 依 fit 排序取前 3（若 hot 濾掉不足 2 隻則退回依 hits 取最小 3 隻）
子代    保留前 2 隻親代（清空統計）＋ 補滿至 10
世代    gen++；gen===3 時解鎖新技 ab1；gen===6 時解鎖新攻擊型態 ab2
```

**只演化本波出場的系**（`s.ids`），其他系基因池不動。
出場個體依 `use`（使用次數）升序取樣，讓每隻都有機會被繁殖。

### 2.2 玩家武器基因（6 把 × 6 基因）

六基因順序 `GN = [射速, 發數, 散布, 彈速, 彈徑, 機動]`，值域 0–1。

| # | 武器 | `k` 彈種 | 解鎖條件 | 錨點 `a` | 發射間隔係數 `r` |
|---|------|---------|---------|---------|----------------|
| 0 | 散彈 | `fan` | 開局 | `[.45,.5,.55,.5,.5,.5]` | 1 |
| 1 | 針 | `needle` | 擊落針蜂 5 隻 | `[.8,.2,.1,.9,.1,.7]` | 1 |
| 2 | 浪 | `orb` | 擊落水母 5 隻 | `[.2,.15,.2,.2,.9,.3]` | 1 |
| 3 | 牆 | `wall` | 擊落砲蟹 5 隻 | `[.3,.9,0,.5,.6,.2]` | 1 |
| 4 | 雷射 | `beam` | 擊落獨眼 5 隻 | `[.35,.2,.4,.5,.4,.4]` | **0.45** |
| 5 | 追蹤 | `homing` | 擊落孢子 5 隻 | `[.4,.4,.5,.4,.5,.6]` | 1 |

雨雲系（第 5 系）沒有對應武器，是設計上的空缺。

**武器不會切換。** `applyW()` 把所有已持有武器塞進 `WPS`，每幀全部開火：
```js
for(let i=0;i<6;i++){const p=WPS[i];if(!p)continue;
  pcs[i]=(pcs[i]||0)+dt*p.rate;while(pcs[i]>=1){pcs[i]--;wfire(...)}}
```
`OWN` 只增不減，只有 `gameOver()` 會重置。**拿到就是永久的。**

## 3. 攻擊當量規則（核心設計）

### 3.1 規則本意

一次發射兩枚子彈 = 單發射速 ×2 = **攻擊當量相同**。
這條規則由 `wp()` 的分母實作：

```js
dmg = CFG.fire * (.65 + .35*L) * ratio / (rate * n)
```

`rate` 與 `n` 同時出現在分子分母 → **DPS 恆定**。
單發高傷低頻率 vs 多發低傷害，對總輸出的影響完全相同。

實測（`node` 計算，第 0 代錨點值，Lv 1）：

| 武器 | rate/s | 發數 n | 單發 dmg | **DPS** |
|------|--------|-------|---------|---------|
| 散彈 | 6.10 | 4 | 0.90 | **22.00** |
| 針 | 8.90 | 2 | 1.24 | **22.00** |
| 浪 | 4.10 | 2 | 2.68 | **22.00** |
| 牆 | 4.90 | 6 | 0.75 | **22.00** |
| 雷射 | 2.38 | 2 | 2.08 | **22.00** |
| 追蹤 | 5.70 | 3 | 1.29 | **22.00** |

六把全部 22.00。**等價規則成立。**

### 3.2 等價在哪裡漏掉

規則對 **DPS** 成立，但對**實際造成的傷害**不成立。三個漏口：

**漏口 1 — 單發稅**

```js
dmg: k==="needle" ? dmg*.7 : dmg     // 針打七折
out.push({... dmg:dmg*.9, ...})      // 雷射打九折
```

| 武器 | DPS | 稅 | 實際單體當量 |
|------|-----|---|------------|
| 散彈 | 22.00 | 1.00 | 22.00 |
| 針 | 22.00 | 0.70 | **15.40** |
| 浪 | 22.00 | 1.00 | 22.00 |
| 牆 | 22.00 | 1.00 | 22.00 |
| 雷射 | 22.00 | 0.90 | **19.80** |
| 追蹤 | 22.00 | 1.00 | 22.00 |

**漏口 2 — 多體成長**

光束命中整條柱子的所有敵人，不分攤成本；針的穿透會持續命中不同敵人。
散彈與牆則是一發一敵、中彈即滅。

雷射實際當量 vs 柱內敵人數 N：

| N | 雷射（修正前 5.30/s） | 雷射（**修正後 2.38/s**） | 針（穿透） | 散彈 |
|---|----------------------|--------------------------|-----------|------|
| 1 | 19.8 | **8.9** | 15.4 | 22.0 |
| 2 | 39.6 | **17.8** | 30.8 | 22.0 |
| 3 | 59.4 | **26.7** | 46.2 | 22.0 |
| 4 | 79.2 | **35.6** | 61.6 | 22.0 |

**漏口 3 — 擊殺爆發**

浪擊殺時產生 6 枚扇形碎片，各 `dmg*.35` = 單發 2.10 倍。只在擊殺觸發，
獎勵爆發節奏而非續戰。

### 3.3 v0.2 修正：雷射發射間隔

問題診斷：雷射是唯一「不需要瞄準時間」的武器，且吃滿整條柱子而無分攤。
**修正方式：拉長發射間隔，用時間補回平衡。**

```js
// WL 陣列第五項新增 r 欄位
{n:"雷射",k:"beam",from:3,a:[.35,.2,.4,.5,.4,.4],r:.45}

// wp() 的 rate 乘上係數
const rate=(2.5+v[0]*8)*(l.r||1)
```

`l.r||1` 是關鍵——其他五把沒有 `r` 欄位，`||1` 讓它們完全不受影響。

效果：**發射間隔 0.189s → 0.419s（2.2 倍）**。
三隻疊在一起的當量從 59.4 降到 26.7，與散彈的 22.0 同一量級。
疊陣仍有回報，但不再是「疊越多越無敵」。

`r` 是唯一待調參數：太鈍調 0.55，太銳調 0.35。**只動這一個數字，其他不動。**

## 4. 玩家強度 ↔ 敵人強度耦合

`PWR()` 把玩家強度換算成敵人血量成長係數：

```js
r = max(所有持有武器的正規化基因總和)   // 最強單把武器
t = Σ(每把持有武器的 .65 + .35*等級)
PWR = r * max(1, t)^0.75
```

敵血 = `基礎血量 * (1 + (PWR-1) * CFG.pwk)`，`CFG.pwk = 0.85`。

邊際收益遞增但收斂（`node` 實測）：

| 持有武器數 | t | PWR 倍率 | 玩家 DPS 倍率 | **淨收益** |
|-----------|---|---------|-------------|-----------|
| 1 | 1.00 | 1.000 | 1 | 1.000 |
| 2 | 2.00 | 1.682 | 2 | 1.189 |
| 3 | 3.00 | 2.280 | 3 | 1.316 |
| 4 | 4.00 | 2.828 | 4 | 1.414 |
| 5 | 5.00 | 3.344 | 5 | 1.495 |
| 6 | 6.00 | 3.834 | 6 | 1.565 |

遞增來自 `.75` 次方 vs 線性 DPS，非線性疊加。這個耦合是自洽的：
玩家變強 → 敵人變強，但變不到哪去。

### 4.1 加武器是負面交易（已知設計問題）

`applyW()` 把所有持有武器的 `ag`（機動）**取平均**決定 `SP`（速度）與 `PR`（判定半徑）：

```js
ag /= OWNL.length; SP = .6 + ag*.7; PR = .02 + ag*.02
```

因此拿到一把低機動武器（雷射 `ag=.4`）：
- PWR 增加 → 敵人血量 ×1.68
- 自己的閃避速度與判定半徑被稀釋 → **判定變大，更容易被打中**

淨收益僅 1.189 倍，還要承擔精度損失。**尚未決定是否保留此設計。**

## 5. 難度調整（v0.2 變更）

### 5.1 彈速滑桿

```js
SPDM = Math.pow(1.6, sliderValue/100)
```

`SPDM` **同時**乘在敵彈與玩家彈上：

```js
// 敵彈  fire()
v: v*DK*EASE()*SPDM
// 玩家彈  wfire()
v: bs*DK*SPDM
```

| 滑桿值 | SPDM 倍率 |
|-------|----------|
| 0 | ×1.000 |
| -100 | ×0.625 |
| -150 | ×0.494 |
| -200 | ×0.391 |
| -250 | ×0.309 |
| **-260** | **×0.295** |

**v0.2 變更**：`min` 由 `-100` 改為 `-260`。
原設定朋友已拉到最左（×0.63）仍覺得中期太難。
目標 0.30 對應 slider = `100×ln(0.30)/ln(1.6)` = -256.2，
`step="10"` 取最近值 -260 → ×0.295。

### 5.2 ⚠️ 滑桿的副作用

因為 `SPDM` 同時縮放雙方，拉到 0.295 時**玩家自己的子彈也變三成速**。
實際效果是「整個遊戲變慢」，不是「變簡單」。

- 難度卡在**躲不過** → 有效（判讀時間變多）
- 難度卡在**打不贏** → 幾乎無效（雙方一起慢）

**若需要「只降敵人強度」**，應調整 `CFG.pwk`（敵血成長係數，現 0.85），
該係數只縮敵人、不縮玩家。**此選項尚未實作。**

## 6. 已知問題

以下全部經**靜態閱讀與 node 插樁量測確認**，尚未在瀏覽器實測。

### 6.0 效能：縮圖光柵化量

**問題**：v0.2 / v0.3 在第五波（第一次顯示武器縮圖）之後手機會卡死。

**量測方法**：node 內以 stub canvas 計算 canvas 繪圖呼叫數。
手機 canvas 2D 每個 op 都要實際光柵化，node 量不到光柵化成本，
但**操作次數**是有效代理指標。正常對局的 `draw()` 實測 225–273 ops/幀。

| 版本 | 單張縮圖 ops | 動畫 | 三張同幀 |
|------|------------|------|---------|
| v0.1 原始（40 幀、不清畫布、每幀只畫活著的彈） | ~62 | 有 | ~186 |
| v0.2（130 幀 + 每幀重畫船 + 每幀清畫布） | 1,777 | 有 | 5,331 |
| v0.3（36 幀、分幀） | 631 | 有 | 1,893 |
| v0.4（靜態圖樣） | 29 | **無** | 87 |
| **v0.5（24 幀拖尾、背景與船只畫一次）** | **127**（最高 223） | **有** | 762 |

**v0.2/v0.3 弄死手機的兩個原因**（皆為重寫時引入）：
1. 每幀重畫一次不會動的船 → 1300 ops
2. 每幀清畫布 → 子彈被「飛完整條畫布」，累積繪製量暴增

**v0.1 為什麼便宜又好看**：背景只畫一次、迴圈內**不清畫布**，
40 幀的彈痕直接疊在一起，自然形成拖尾感，那就是動畫。
動畫感來自疊圖，不是靠幀數堆。

**v0.4 是誤判**：把縮圖改成靜態圖樣雖降到 29 ops，
但失去了動畫效果（使用者回報「預覽武器不是動畫」）。
縮圖必須是動畫。

**v0.5 做法**：沿用 v0.1 的架構——
- 背景與船移到迴圈外，只畫一次
- 迴圈 24 幀，**不清畫布**，靠拖尾形成動畫
- 子彈飛行範圍限制在 `b.y > -.4`（不讓它飛完整條畫布，控制繪製量）
- 保留每種武器的專屬形狀與武器色
- 三張卡用 `setTimeout(..., 50*n)` 分幀執行

結果：最高 223 ops/張，分幀後每幀 254 ops，約等於 1.1 個正常遊戲幀。

## 7. 遊戲流程

```
newGame()
  → WAVE 1 建場（實務上被跳過，見 6.1-1）
  → 玩家開始
  → 每波：mkWave() 產生敵人隊列 → stepW() 模擬 → 結束條件（隊列空 + 敵人空 + 1.2s）
  → 波末：evolve() 演化 + 回血 1 + 檢查武器解鎖
  → 分岔：
      WAVE % 30 == 0 → stageEnd()（階段結算）→ offerSkill()
      WAVE % 5  == 0 → offerSkill()（三選一技能卡）
      WAVE % 10 == 0 → offer3()（基因進化三選一）
      否則 → go() 直接下一波
```

**操控模式**（`HAB`）：
- `0` 站樁：`s.px=0`，完全不動
- `1` 左右掃：`s.px=.8*sin(t*1.1)`
- `2` 會閃避：`plan()` 每幀評估 5 個候選速度
- `3` 手動：鍵盤 + 虛擬搖桿，**唯一會扣血的模式**

`plan()` 閃避 AI：對 t = [0.1, 0.2, 0.3] 三個時間點預測敵彈位置，
候選速度 `[0, -1, 1, -0.5, 0.5]`，用倒數距離平方和評分，
額外懲罰靠邊（`|fx|>0.85` 加 30）與光束橫向距離。

## 11. 已取消的構想

### 11.1 雷射「移動蓄力、停止爆發」

曾討論的機制：玩家移動時累積蓄力，停止時爆發。
**已取消**，理由是過度複雜化。改以單純的發射間隔調整解決平衡問題。

### 11.2 絕對平衡

**本專案不追求絕對平衡。** 武器透過擊落特定敵人系解鎖，帶有抽卡隨機性。
不同武器與攻擊方式刻意帶來不同手感，單體／多體當量的差異是設計的一部分，
不是需要修正的缺陷。武器折扣（如針的 0.7）是為了平衡多體穿透。
